# A 同学 · 前端页面与部署执行手册

**宠宠欲动 Petitch｜怪人协会｜2026 年 11 月 18–30 日｜北京时间**

你负责用户真正点得到的页面和最后提交的公开链接。你维护路由、公共样式、问卷会话和构建配置；B 给你数据与排名，C 给你试养和收藏/清单控件。20 日之前把时间集中在首页、问卷、结果。

## 第一次打开 Qoder

1. 在 Qoder 登录自己的账号。进入现有 Petitch GitHub 仓库，点 Code 复制 HTTPS 地址。在 Qoder 命令面板搜索 Git: Clone（克隆），粘贴地址，选择本机项目目录，打开刚克隆的 Petitch。已克隆时直接打开含 README 的仓库根目录。
2. 在集成终端依次运行下列只读检查。第一行应显示当前分支及文件变动，第二行应显示团队仓库。Node 或 npm 未识别时先安装与项目 Vite 兼容的 Node LTS，重开 Qoder 终端再查。

```sh
git status -sb
git remote -v
node -v
npm -v
```

3. 初始仓库只有 README 和 Node .gitignore 时，由你在当前目录建脚手架并提交锁文件。把运行过的 Node、npm 版本及启动命令告诉 B、C。之后三人从锁文件安装依赖。
4. 把《00-Petitch-系统架构.md》和本手册附到 Qoder 对话。每天从干净且同步的主分支建一个短分支，例如 `a/1118-start`。通过状态栏的分支名创建和切换；若有未提交工作，先在原分支保存。
5. 跳到当天日期，把当天输入作为附件、选中的仓库文件或消息提供，再整段复制提示词。看一遍它列出的改动路径。本人执行验收，检查源代码管理面板的 diff，勾选本任务文件，写提交说明并推送该分支。在 GitHub 打开 Compare & pull request，写上输入、实际结果和复测步骤，请接收人审核合并。次日切回主分支拉取，再开新分支。

## 页面接线与自测教程

1. 先把首页的一张卡和第一题做通。组件收数据和回调，路由层负责跳转。Tailwind 接入后给首页按钮设暖色背景和明显焦点，确认样式在生产预览里也生效。首页热门区默认只渲染三张固定卡（狗、猫、兔），其余九张由「查看更多」按钮（右侧附「还有 9 种」）展开、由「收起」折回；按钮带 `aria-expanded` 和 `aria-controls`，未展开时那两层背板只作视觉暗示且 `aria-hidden`。展开状态只存组件内存，刷新回到默认三卡，不写 sessionStorage 也不写 localStorage。
2. 问卷用“题目 id → 选项 id”保存，交给 rankPets 前由 quizSession 换成“题目 id → 1–5 档”字典；没填档位的题不出现在字典里，不要用选项序号冒充档位。先构造本次点击后的完整答案，再保存、推进或提交；返回上一题读回上次选项。题数、进度和“X 题答完了”都取 `questions.js` 的长度，不写死六或八。结果页调用 B 的 rankPets。若返回空数组，回问卷。重新测只清本轮答案。
3. A 的 ChecklistPage 把 petId、items 传给 C 的 ChecklistItems，详情页挂 FavoriteButton 和 BreedButton；后者只看 breeds.json 里有没有该类型的行，代码不写死类型名单。C 的 TrialPage 自行读取本轮第一名。谁拥有标识、谁拥有状态，分别按架构表执行。
4. 本地开发在集成终端运行 `npm run dev`，打开它实际输出的地址。发布前依次运行 `npm ci`、`npm run build`、`npm run preview`，打开 preview 的地址复测。开发服务器能打开只是第一步，需以生产构建为准。

### 用 Qoder 发布同一个站点

从已验收的 main 提交构建，记下 `git rev-parse --short HEAD`。在支持站点功能的 Qoder 客户端打开“站点”，进入已有 Petitch 站点任务或首次添加站点，用当天发布提示词引用当前项目。打开产物卡片预览，核对结果第一名、详情直达、图片及收藏。检查站点名称和发布目标后确认发布，将可见性设为公开，复制公开访问地址。

若当前 IDE 的站点任务无法读取本地仓库，在 **Qoder 集成终端**打开已登录的 Qoder CLI 交互会话，从当前仓库用自然语言要求其将刚构建的 dist 打包到目标站点。核对它显示的目标和发布确认，再用手机流量验证。同一天的修复更新原站点，更新草稿后须重新发布才会在线上生效。[Qoder 站点](https://docs.qoder.com/zh/qoder/sites) · [Qoder CLI Sites](https://docs.qoder.com/cli/sites)

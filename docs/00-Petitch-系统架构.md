## 3. 三人第一次联调就要签下的接口

以下是运行时接口，原始资料无须新增字段。若原表只有中文名，B 在 catalog 中用固定映射生成路由标识。清单项沿用已有标识，缺少时在映射层固定赋值，避免按页面当前位置保存。

| 接口 | 输入 | 返回与调用方 |
|---|---|---|
| questions | 无 | 有序的八个题目对象，每个含 id、title、options；选项含 id、label，已定档的选项另含 1–5 的 score，按规则跳过的选项 score 为 null（目前只有过敏题「都没有」）。A 渲染，B 维护映射 |
| getPet(id)、listPets() | 固定宠物标识或无参数 | 指定资料或原表顺序的全部资料。未知 id 返回 null，A 展示返回首页入口 |
| rankPets(answers) | readAnswerScores() 的字典：键为题目 id、值为 1–5 档 | 完整有效时返回三项，每项含 petId、percent、reason；除过敏外七题的键不齐或含无效档位时返回空数组。字典里没有 `allergy` 键即按跳过处理，不算缺答，A 和 C 调同一函数 |
| readAnswers()、saveAnswers(answers)、clearAnswers() | 当前八题的选项标识 | A 写 sessionStorage，C 从同模块读；重新测清除旧轮次 |
| readAnswerScores()、toAnswerScores(answers) | 无参或当前八题的选项标识 | 键为题目 id、值为 1–5 档的字典，供 rankPets 使用。score 没填或填 null 的选项都不进字典，A 维护 |
| listBreeds(typeId)、hasBreeds(typeId) | 目录中有效的宠物 id | 该类型下的品种数组与是否存在品种数据；breeds.json 未落地时返回空数组和 false，A 维护 |
| rankBreeds(typeId, answers) | 宠物 id 与 readAnswerScores() 的字典 | 该类型下的品种排名，每项含 breedId、percent、reason、feature；无品种数据或答案无效时返回空数组。与 rankPets 共用打分口径 |

## 4. 八题怎样变成三个有理由的推荐

**答案字典。** 问卷交出的不是选项标识而是 1–5 档字典：`{ housing: 4, time: 2, … }`。A 在 `quizSession.js` 里由 `questions.js` 的 `score` 字段换算，B 的字段对照表补齐原六题（掉毛、粘人两题的档位本次已定）。`score` 的两种缺省含义不同：没填是等 B 的对照表，显式写 `null` 是「这一维按跳过处理」，目前只有过敏题的「都没有」用 `null`（判据见本节末）。宠物侧属性档直接读 `pets.json` 原值，原表值一直保留，换算只发生在读取层。

**权重（定版，合计 14）。** 住房 2、陪伴 3、经验 1、过敏 3、预算 2、安静或活泼 1、掉毛 1、粘人 1。过敏跳过时有效权重和取 11。

| 题／权重 | 类型 | 原表对应项 | 契合分 |
|---|---|---|---|
| 住房 2 | 需求型 | 空间需求 | 先把可提供量和需求统一为 1–5 档；5 − max(0, 需求 − 可提供) |
| 陪伴 3 | 需求型 | 陪伴需求 | 同上，时间富余不扣分 |
| 经验 1 | 需求型 | 饲养难度 | 同上，将经验映射为可应对难度 |
| 过敏 3 | 正向／跳过 | 过敏友好度 | 选「都没有」（选项 id `none`）时整题跳过，不计入分子，分母扣掉权重 3；选「有点担心」或「已确诊」时契合分直接取该宠物过敏友好度列的原档，用户档位不进距离公式。避免作个人过敏风险保证 |
| 预算 2 | 需求型 | 预算需求（costTier） | 5 − max(0, 宠物花费档 − 用户预算档)；月花费文案仅负责展示 |
| 安静或活泼 1 | 偏好型 | 叫声、运动量 | 两维各按偏好型算契合分后取平均，整题仍占权重 1 |
| 掉毛 1 | 偏好型 | 掉毛 | 5 − abs(用户忍受度档 − 宠物掉毛档) |
| 粘人 1 | 偏好型 | 粘人 | 同上 |

需求型的通式是 `5 − max(0, 宠物需求档 − 用户能给的档)`，用户给得更多不扣分；偏好型的通式是 `5 − abs(用户偏好档 − 宠物属性档)`，两头偏离都扣分。

**过敏跳过判据（2026-11-18 定版）。** 判据写在数据层而不是写在 `match.js` 里：`questions.js` 中「都没有」选项的 `score` 记 `null`，A 的 `toAnswerScores()` 见到 `null` 就不把 `allergy` 键放进字典，`rankPets` 查不到 `allergy` 键即按跳过处理，分母少算权重 3。这样 B 的打分函数不需要知道任何选项 id，也不需要在代码里写题干文案。两个「有顾虑」选项（`unsure`、`confirmed`）的 `score` 必须是**非空**值，否则会被当成没顾虑整题跳过；它们本身不参与计分，契合分取的是宠物侧的过敏友好度，B 按对照表填任意 1–5 档即可，填完不改行为。因此「答案完整」的判据是其余七题的键齐全（住房、陪伴、经验、预算、安静活泼、掉毛、粘人），`allergy` 缺键一律按跳过算、不按缺答算；七键不齐才是 §3 里「不全返回空数组」那种情况。

**预算档换算。** 问卷五个选项按序号即档 1–5（¥100 以内 = 1，¥200 以内 = 2，¥400 以内 = 3，¥600 以内 = 4，¥600 以上 = 5）。宠物侧 `monthlyCost` 是区间文本，B 在 catalog 里取**区间右端**按同一组阈值落档：≤100 → 1、≤200 → 2、≤400 → 3、≤600 → 4、>600 → 5，`costTier` 写成数字，详情页文案仍读原字符串。**「以内」含上限，2026-11-18 定版。** 五档按左开右闭划界，每个上限值归「以内」；否则 600 既在「¥600 以内」又是「¥600 以上」的起点，200、400 这些边界也一样在两档间抖，雪貂和龙猫会各差一档、匹配度跟着抖。取含上限后边界唯一：龙猫 ¥200–400 落 3 档，雪貂 ¥300–600 落 4 档。其余十种同推：狗 ¥300–800 落 5，刺猬 ¥100–200 落 2，金鱼 ¥20–50 落 1。

**0 值处理。** 原表把乌龟、金鱼、守宫的掉毛和叫声记作 0，含义是「完全没有」。偏好型公式 `5 − abs(偏好 − 属性档)` 在 0 上会让最安静、最不掉毛的三种永远拿不到满分（用户选最安静档得 1 时只能算出 4 分），结论反向。故换算前把属性档 clamp 到 1–5，0 按 1 算；`pets.json` 仍存原值 0，详情页展示照旧读原值。受影响的是掉毛和叫声两维，其余维度原表最小值为 1，clamp 是空操作。B 在量表方向表里注明这条。

为每只宠物计算 S = Σ(契合分 × 题目权重)，W = 有效题目的权重和。匹配度 = S / (5W) × 100 四舍五入。用 S / (5W) 这个未取整的比值从高到低排序，取前三；完全同分按原表顺序。百分比解释为生活条件的规则契合度。理由从有效题中选契合分最高项，并列先取高权重、再次并列按题序。例：「你每天能投入的陪伴时间有限，它所需的陪伴时间也较短。」若最高项也只有 3 分或更低，改为指出最大短板，避免误导。

**手算示范（虚构分值，仅验公式）。** 按表中题序，某宠物八项契合分为 5、5、4、跳过、3、4、2、3。加权和 = 10 + 15 + 4 + 6 + 4 + 2 + 3 = 44，有效权重 = 2 + 3 + 1 + 2 + 1 + 1 + 1 = 11，44 / 55 显示 80%。理由取并列最高的两题中权重较大的陪伴（3 > 2）。若「有过敏顾虑」且该维为 2 分，新结果为 44 + 6 = 50 / 70，显示 71%。测试另覆盖同分、取整后相同但原始分不同、不全答案及回退改选。

## 5. 试养和存储的边界

- 从本轮第一名取五张卡。狗、猫、兔子、仓鼠、鹦鹉各用自己的五张，余下七种统一读五张通用卡。库存总数为 5 × 5 + 5 = 30。通用卡文案应适用于含金鱼、守宫在内的七种对象。
- 三个选项依次扣 0、5、20 分。保留按卡标识记录的五次选择，忍受度 = 100 − 扣分合计。只有本卡首次确认可推进。刷新试养页从本轮 Top 1 的第一张重新开始；刷新结果页仍可重算排名。
- 原需求在 85 分重叠。统一为分数 <60 劝退，60–85 含两端提醒，>85 适合。劝退展示延后决定、云养宠或到收容所做志愿者；提醒显示扣分点；适合进入对应清单。三档均可进入指南。
- 四个可复现例子（括号内为五张卡分别扣分）：55（20,20,5,0,0），60（20,20,0,0,0），85（5,5,5,0,0），90（5,5,0,0,0）。
- localStorage 的 petitch.favorites.v1 保存类型标识数组；petitch.checklists.v1 保存“宠物标识 → 已勾选条目标识数组”。每次更新按当前宠物合并，保留其他类型。缺键或坏 JSON 回到空状态。sessionStorage 的 petitch.answers.v1 记录当前答案；读出后验证题目和选项。无效链接给明确返回入口。
